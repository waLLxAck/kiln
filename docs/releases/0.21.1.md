# Kiln 0.21.1

Fixes skills disappearing from the library when their collection path exceeds 80 characters.

- **Long collection names and nested paths work throughout Kiln.** Removed the character cap from library loading, editing, moving and renaming collections, export/import and analysis records. Automatically named collections keep their full names too.
- **Existing skills reappear when the library is reopened.** The old validation warning hid affected entries without deleting their files. Update Kiln on each affected machine and reopen the same library; no manual renaming or reimport is needed. Content, revisions and approvals are preserved.

| Platform | File |
| --- | --- |
| Windows (x64) | `Kiln-Setup-0.21.1.exe` |
| macOS, Apple silicon | `Kiln-0.21.1-arm64.dmg` or `Kiln-0.21.1-arm64.zip` |
| macOS, Intel | `Kiln-0.21.1-x64.dmg` or `Kiln-0.21.1-x64.zip` |
| Linux (x64) | `Kiln-0.21.1-x86_64.AppImage`, `kiln_0.21.1_amd64.deb` or `Kiln-0.21.1-x64.tar.gz` |

Windows, AppImage and .deb installations offer the update in Kiln. macOS and tar.gz installations link to the release page. The included `latest*.yml` files are update feeds; you do not need to download them manually.

Validation: 170 unit tests passed on Linux, with one Windows-only test skipped. The production build and type check passed. Regression tests cover reopening existing long-path skills on another machine without changing approvals or revisions, authoring and moving long collection paths, export/import and analysis naming. The release workflow builds and smoke-checks the packaged apps on their platform runners before publishing.
