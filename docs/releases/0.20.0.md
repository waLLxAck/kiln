# Kiln 0.20.0

Folders that behave like folders, sources that stay linked to what was made from them, and updates straight from GitHub.

- **Updates from GitHub releases.** Kiln checks the releases page 15 seconds after it starts and then every 30 minutes. Each check is one small request, and nothing downloads until you click. On Windows, the Linux AppImage and the .deb, **Download** fetches the update in the background and **Restart to update** installs it and reopens Kiln. The .deb asks for your password. On macOS and the Linux tar.gz, **Get 0.x** opens the release page, because macOS only lets apps signed with an Apple Developer ID replace themselves. Local builds still watch their repository's `release` folder, for developers. On Windows, the AppImage and the .deb, this is the last version you need to download by hand.
- **Delete a collection and keep its items.** Deleting now asks: **Keep items** moves them, and any subfolders, up one level. Items in a top-level collection become unfiled and show under a new **Unfiled** entry. **Move items to trash** works as before.
- **Subfolders.** A `/` makes one (`Game Design/Puzzles`). The sidebar shows collections as a tree you can collapse, and a parent's count and item list include its subfolders. Right-click a collection for **New subfolder…**. Renaming to a path moves a collection under another one.
- **Move to collection…** on an item or a selection files items anywhere, in a new collection, or in none.
- **Organising never costs an approval.** Where an item is filed is kept on the item, not in its revision. Moving items, and renaming or deleting collections, no longer sends approved skills back to Captured, and installed copies keep matching.
- **Sources.** Material you analyse (a pasted chat, a page, files, a video) is now a **source**, not a prompt, so it has no Copy, Test or Create skill. The new **Sources** tab lists them. A source's page shows its analysis runs, everything made from it and where each item is filed now, and the original material. Every item made from a source shows **From "…"**, which opens it, and the **Source** filter shows everything one source produced across collections. A summary of each analysis (model, tokens, summary, takeaway, counts) travels with the library, so it shows on your other machines. Existing analysed captures and videos become sources automatically; approved items are left as they are.
- **Raw Markdown by default.** Item content opens as raw Markdown. **Preview** shows it formatted.
- **Variables are optional.** Copy a prompt or start a trial without filling its `{{variables}}`; blank ones stay in the text as `{{name}}`. The copy dialog has **Copy without filling**.
- **Fewer pointless variables.** Analyses now write prompts for an agent that is already inside your repository. The agent looks up the project name, stack, layout and commands itself, and placeholders are kept for things only you decide.
- **For agents: the CLI can organise the library.** `collections create`, `collections rename`, `collections delete --keep-items | --trash-items`, `items move <ids> --collection "…" | --unfiled`, and `items list --recursive | --unfiled | --kind source | --from <id>`. Reading a source returns `madeFrom`.

The `latest*.yml` files are the update feeds the app reads. You don't need to download them.

Validation:

- **Before tagging:** the type check, 157 unit tests and the Electron desktop suite passed on Linux. A packaged public Linux build, labelled 0.19.0 for the test, checked GitHub from inside Electron, found 0.19.1 and showed **Get 0.19.1**.
- **By the release workflow:** it built each platform on GitHub's runners and started each packaged app once.
- **After publishing:** an AppImage labelled 0.19.0 found this release, downloaded it and restarted into 0.20.0 in place. The installed file's SHA-256 matched `SHA256SUMS.txt`. The Windows and `.deb` in-place installs haven't been tried on a real machine yet.
