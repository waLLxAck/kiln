# Kiln 0.25.0

MCP servers join the library, a Usage page shows which skills your agents actually use and what the sessions cost, GitHub repositories can be imported and distilled, and skills can be scored and tuned. The [user guide](../GUIDE.md) describes everything in full.

- **MCP servers as library items.** A new **MCP server** kind holds one client-neutral definition (stdio, http or sse; environment values as `${NAME}` references, and literal-looking secrets are rejected). **Settings → MCP servers → Find MCP servers not in the library** imports what Claude Code, Codex, Copilot CLI, VS Code and Cursor already have, personal and per project, showing each distinct definition once with every place it was found. An approved server gets an install matrix per client and location. Installing writes only that server's entry in the client's own format (JSON keeps its comments and neighbours; Codex gets its own `[mcp_servers.<name>]` table), refuses stale files, keeps the previous file in Config files' versions, and records a receipt for drift, removal and rollback. `mcp` CLI commands do the same.
- **Usage.** A new page, read locally from Claude Code's and Codex's own session logs (no API): uses per skill, trend, last used, active days, projects, and filters for **Not in library**, **Not approved** and **Installed, unused**, with **Import** for a used skill Kiln doesn't manage. The **Spend** tab adds up tokens by model, project, harness and month, plus Kiln's own runs, with estimated dollars from an editable list-price table (subscriptions pay a flat fee; these are estimates). Session tokens are split evenly across the skills used in that session and labelled as attributed. Only counts, names, folders, models and days are kept, on this machine; nothing is written to the library. `usage` CLI commands too.
- **Skills from GitHub repositories.** Paste or drop a `github.com/owner/repo` link (or a `/tree/…` folder) into Capture, or the import dialog, and choose **Scan repository**. Without a model, Kiln fetches one commit and finds skills (`skills/`, `.claude/`, `.agents/`, `.cursor/`, `.github/skills`, Claude plugins and marketplaces, any other SKILL.md folder) and Claude, Copilot and Codex agents, then shows them for review: new, already in the library, or different. Imports are drafts linked to a source item for the repository, with the commit, path and licence recorded. **Dig deeper** then sends your agent through the checkout read-only to propose new skills and the entry types you chose, like distilling a video. **Browse skill repositories** lists well-known public skill repositories, and **Scan my GitHub repositories** checks your own. `repos` CLI commands too.
- **Agent instructions from distillation.** A source that recommends a rule for CLAUDE.md, AGENTS.md, Copilot instructions or Cursor rules now produces an **instruction** entry: the ready-to-paste snippet plus where it belongs. **Add to CLAUDE.md / AGENTS.md…** opens the file in Config files with the snippet added as an unsaved edit.
- **Choose what a distillation produces.** **Settings → Distillation** has a checkbox per entry type (prompts, techniques, insights, tools, resources, instructions). Only chosen types are asked for, and others are dropped if an agent returns them anyway.
- **Score.** A read-only run rates a prompt, skill, agent or instruction revision against the writing-for-agents guidance and returns a 0–100 score with a list of improvements. The score is kept with that exact revision, shows as a badge (faded once you edit), and has a library column. Each improvement links to its line; **Apply improvements** has the agent write them into a new draft.
- **Tune** (skills only). Runs the bundled tune-skill on a copy of the skill in a private folder: it measures past runs from Claude Code transcripts, rewrites the document, moves repeated work into scripts and field-tests the result. Kiln then shows the diff of SKILL.md and every bundled file; **Accept as draft** makes one new draft revision. Tune needs write access and can run commands inside its folder; the agent access warning says so and appears once more for everyone.

Also in this release:

- Bundled guidance: writing-for-agents (mattpocock/skills, MIT) now ships with its licence, and tune-skill is bundled for Tune.
- Known limits: MCP installs and scores are recorded on this machine and aren't synced to your other machines yet. Usage doesn't read Copilot logs, and there are no Codex model prices in the table until you add them. Dig deeper, Score and Tune run from the desktop app only.

If you're on 0.20.0 or later with Windows, the AppImage or the .deb, Kiln offers this update itself. On macOS and the tar.gz it links to this page. The `latest*.yml` files are the update feeds the app reads; you don't need to download them.

Validation: before tagging, the type check and 378 unit tests (377 passed, one skipped) passed on Windows, macOS and Linux in CI, and so did the Electron desktop suite (57 passed, 4 skipped); the new features have unit tests but no desktop specs yet. The new screens were checked against the real backend with the seeded demo library and scripted agent replies; no real model run of Dig deeper, Score or Tune has been made yet. A dry run of the release workflow built all three platforms and started each packaged app once; the packaged builds have not been clicked through by hand.
