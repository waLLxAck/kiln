# Kiln 0.21.0

Collections you can drag around, folders you name where they appear, and a library you can sort the way you use it.

- **Drag collections to nest or reorder them.** In the sidebar, drop a collection onto another to put it inside, or onto the top or bottom edge of a row to place it before or after that row. That can move it to another parent in the same drag. Drop it on the COLLECTIONS heading to bring it back to the top level. Its subfolders and items go with it, and approvals and installed copies are unaffected. **Manage collections** supports the same dragging.
- **New folders are named in place.** The **+** beside COLLECTIONS, and **New subfolder** on a collection's right-click menu, create a **New Folder** straight away with its name selected, so you just type. Enter or clicking away saves it; Esc keeps "New Folder". **Rename** (or F2) edits the name in the sidebar too. There is no more typing `Parent/Name` paths in a dialog; nesting is done by dragging.
- **Sources first in every collection.** Inside a collection, its sources lead the list, sorted among themselves. The whole library mixes them in with everything else.
- **Newest additions first.** Every view now starts with the most recently added items first. Before, the All tab showed the most recently *updated* first and kind tabs used the hand-arranged order.
- **Sort the way you like.** A **Sort** menu next to search offers **Recently added**, **Recently updated**, **Most copied**, **Most used** (copies, opens, tests and agent use Kiln has seen), **Title A–Z** and **Custom order**. Custom order is the hand-arranged order, and the up and down arrows appear only in that mode. Column headings still sort, and each view remembers its own choice.

Validation: before tagging, the type check, 168 unit tests (one skipped) and the Electron desktop suite (34 passed, 3 skipped) passed on Linux. New tests cover moving collections (nest, lift to the top level, reorder, rejecting a move into its own subfolder or onto a taken name), inline naming and dragging in the sidebar and the dialog, sources leading inside a collection, the default and usage-based sorts, and the usage counts in the snapshot. A packaged public Linux build started under the smoke check. The release workflow builds each platform on GitHub's runners and starts each packaged app once.
