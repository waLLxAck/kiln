# Kiln 0.18.2

A fix for Claude Code installed with npm on Windows, and screenshots of the app.

- **Claude Code runs again when it was installed with npm on Windows.** npm installs Claude Code on Windows as a `claude.cmd` script. Kiln starts it through `cmd.exe /s /c`, which strips the first and last quote of the command, so the quotes around the script's own path were lost and every run failed with "… is not recognized". The command line now gets the extra pair of quotes `/s` removes. Every cmd metacharacter in an argument is also caret-escaped the way cross-spawn does it, so `&`, `|`, `%` or quotes in a folder name or JSON can't split the command. A native `claude.exe` was never affected.
- **Screenshots of the app** in the README and on the website. They were taken on Windows with a made-up sample library. The agent's replies in them are scripted, so no model wrote them.

The macOS and Linux builds are still new and untested on real machines. The install notes from [0.18.1](0.18.1.md) still apply: Gatekeeper on macOS, and the AppImage sandbox on Ubuntu 23.10 and later.

Validation: the type check and unit tests passed on GitHub Actions Windows, Ubuntu and macOS runners. On Windows, a new test runs a real `.cmd` script in a folder with spaces and checks that arguments containing quotes, JSON, `&`, `|`, `%`, `^`, `!` and angle brackets arrive intact. The Electron desktop suite passed on Ubuntu under xvfb. Running Claude Code itself through an npm install on Windows was not tested.
