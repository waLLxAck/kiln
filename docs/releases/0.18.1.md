# Kiln 0.18.1

The first macOS and Linux builds, next to the Windows installer. They are new and untested: nobody has used them on a real Mac or Linux desktop yet. Please [report what breaks](https://github.com/waLLxAck/kiln/issues).

| Platform | File |
| --- | --- |
| Windows (x64) | `Kiln.Setup.0.18.1.exe` |
| macOS, Apple silicon | `Kiln-0.18.1-arm64.dmg` or `Kiln-0.18.1-arm64.zip` |
| macOS, Intel | `Kiln-0.18.1-x64.dmg` or `Kiln-0.18.1-x64.zip` |
| Linux (x64) | `Kiln-0.18.1-x86_64.AppImage` or `kiln_0.18.1_amd64.deb` |

- **macOS.** The app is ad-hoc signed, so it runs on Apple silicon, but it is not notarized, so Gatekeeper blocks the first launch. Right-click Kiln in Applications and choose **Open**; on macOS 15 and later, choose **Open Anyway** in System Settings → Privacy & Security. Or run `xattr -dr com.apple.quarantine /Applications/Kiln.app`.
- **Linux.** `chmod +x Kiln-0.18.1-x86_64.AppImage` and run it (AppImages need FUSE 2), or `sudo apt install ./kiln_0.18.1_amd64.deb`. Where unprivileged user namespaces are blocked, as on Ubuntu 23.10 and later, the AppImage's launcher starts Kiln with `--no-sandbox`, so Chromium's sandbox is off; if it still exits with a sandbox error, pass `--no-sandbox` yourself. The .deb installs an AppArmor profile meant to keep the sandbox on.
- **Windows** is unchanged: the same unsigned installer, so SmartScreen may warn before it runs.

Portability fixes for macOS and Linux:

- Apps opened from the Dock or a desktop launcher get a minimal PATH. Packaged Kiln now takes PATH from your login shell and also looks in the usual npm, Homebrew, `~/.local/bin` and `~/.claude/local` folders, so Codex, Claude Code, Git and the GitHub CLI are found.
- Paths under macOS's `/var` and `/tmp`, and home folders reached through a link (such as `/home` → `/var/home` on Fedora Atomic), were rejected as symlinks, so a library there could not open. Those system links are now accepted; links inside your home folder are still refused.
- Config files lists VS Code user settings from `~/Library/Application Support/Code/User` on macOS and `~/.config/Code/User` on Linux.
- The macOS menu bar uses a monochrome template icon.
- The in-app updater runs the Windows installer, so on macOS and Linux Settings → Updates links to the releases page instead.
- Launch at login is hidden on Linux, where Electron cannot set it, and the tray and file-manager wording follows the platform.

The website offers the file for your platform and lists the others, with install notes for each.

Validation: the type check and all 129 unit tests passed on GitHub Actions Windows, Ubuntu and macOS (arm64) runners. The Electron desktop suite passed on Ubuntu under xvfb (25 passed; 3 skipped: two need explicit opt-in, and the in-app updater test is Windows-only). The release workflow built every file on those runners. The AppImage was extracted and the .deb read with `dpkg-deb`. Both disk images were mounted: `codesign` reports an ad-hoc signature that verifies, and Gatekeeper rejects the app as expected without notarization. Each packaged app was started once against an empty library and reached the setup screen: Windows, Linux (the unpacked build under xvfb, not the AppImage itself), and both Mac builds on an Apple silicon runner (the Intel build through Rosetta). Not tested: installing and using Kiln on a real Mac or Linux desktop, an Intel Mac, the Gatekeeper and SmartScreen prompts, the AppImage and .deb on a desktop distribution, the tray and menu bar, the global shortcut on macOS and under Wayland, and running agent CLIs on macOS or Linux.
