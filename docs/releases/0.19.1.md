# Kiln 0.19.1

Fixes for what went wrong when 0.19.0 was tried on a real Linux desktop (Arch Linux, Hyprland on Wayland).

- **A Linux download that needs no FUSE.** The AppImage needs FUSE 2, and on a system with only fuse3 it stops with `error loading libfuse.so.2`. There is now also `Kiln-0.19.1-x64.tar.gz`: unpack it and run `kiln-workbench`. For the AppImage, install `fuse2` (Arch) or `libfuse2` (`libfuse2t64` on Ubuntu 24.04), or run it with `--appimage-extract-and-run`.
- **Imported skills no longer read "Not installed" when their copies are right there.** If you import your installed skills during setup without managing their folders first, setup now offers to manage those folders in one click. Kiln then shows the copies that are already there as found. Managing a folder installs and changes nothing.
- **A tidier import list.** Folders that only hold other skills, like `~/.codex/skills/.system` or `~/.claude/skills/synced/<id>`, are no longer listed as "No SKILL.md inside; skipped". Empty or broken folders are still listed.
- **Skills with the same name can be told apart.** Two different skills with the same name, such as two `skill-creator`s from different folders, stay separate items. When names clash, the list and the item header now show which folder each one came from. That folder is only known on the machine that imported it.
- **The agent warning fits your platform.** The warning about running Codex without a sandbox now appears only on Windows. On macOS and Linux it says that Codex chat runs in Codex's workspace-write sandbox.
- **Machines is "Coming soon".** The Machines section isn't reliable yet, so release builds show a short placeholder in its place. Nothing else in the app links there any more. Builds from source still have it.

The macOS builds are still untested on a real Mac. See the [install notes](../GUIDE.md#installing) for Gatekeeper on macOS and FUSE and the sandbox on Linux. The Windows build is unsigned, so SmartScreen may warn before it runs.

Validation: the type check and unit tests passed on GitHub Actions Windows, Ubuntu and macOS runners. The Electron desktop suite passed on Ubuntu under xvfb. It includes new tests for the manage-folders prompt (the skill folders are byte-identical before and after), the tidier import list, labels for skills with the same name, and Machines in both a development and a public build. The release workflow built every file and started each packaged app, including from the unpacked tar.gz. A dry-run Linux build was tried by hand on Arch Linux with Hyprland on Wayland, with only fuse3 installed. The AppImage stopped with the libfuse.so.2 error and then started with `--appimage-extract-and-run`. The tar.gz started as it was. Setup opened the existing Kiln repository, imported the installed skills and managed their folders without changing them. The two `skill-creator`s showed their folders, and Machines showed "Coming soon". Windows and macOS were not tested by hand.
