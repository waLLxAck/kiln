# Kiln 0.23.0

A redesigned Kiln. The app is now organised around what happens to an item (captured, tested, approved, installed) instead of around seven kind tabs, each item is one page instead of five tabs, and every 0.22.0 feature is always on. There are no more experimental switches. The [user guide](../GUIDE.md) describes everything in full.

**Finding things**

- **Lifecycle sidebar.** Library, then **Drafts**, **Testing**, **Approved** and **Installed** with live counts, then your collections, Archive and Trash, then Experiments, Config files, Machines, Activity and Settings.
- **One compact library table.** One line per item: Collection first, then the title, status (with "+ newer draft"), where it's installed in plain words ("2 of 3 · 1 changed", "1 update"), the last test and when it changed. Drag column headings to reorder them (right-click for Move left/right and Reset). Group by collection, kind or status. Copy, Test and Install on hover, a bulk bar when several rows are picked.
- **One query bar.** Filters are tokens: `kind:skill`, `status:approved`, `in:Claude`, `state:changed`, `tag:`, `from:`, `collection:`, `is:favourite`, `is:duplicate`, with counted suggestions. Free text is ranked by relevance and forgives typos. Save a query as a view.
- **Keyboard.** Home, End, Page keys, Shift to extend, type-ahead, arrow keys in menus, **?** for every shortcut, and **Ctrl+Z** for the last 20 library actions (from the list, a drag onto a collection, or the item page).
- **Quick search** (Ctrl+K) lists items and actions together, fills `{{variables}}` right in its preview before copying, copies the top match on a fast Enter, and runs commands after `>`.

**Working on an item**

- **One page.** The content, editable in place in a code editor (highlighting, find and replace, live SKILL.md checks, bundled text files, and every field kept as a private draft until you save), with one save bar. A column on the right holds Approval, Installs, Tests, History, Provenance and Organisation. The header offers one next step: Test, Approve, Install, **Update installs (N)** or **Resolve N changed copies**.
- **History** is one timeline: revisions, tests, approvals, publishes, installs and outside edits. Tick two revisions to compare them.
- **Experiments** are a grid of revisions against projects. Each result shows the agent's assessment and **your verdict** (Mark as passed / failed) side by side, with Re-test, **Improve with agent**, and Approve. Run from an empty cell; runs beyond two wait as Queued. The Experiments page groups every result by item and revision.
- **Sources** (a video, a page, a pasted chat) have their own page: for videos, a timeline with each entry at its minute and skipped parts shaded, a transcript, and Keep or Archive on each entry.
- **Ask the agent** docks beside the item and keeps each item's conversations. Add other items as context with @. When the agent changes something, a card shows the change with **Keep** or **Undo**.
- **Duplicate consolidation.** When the library holds more than one copy of a skill (the same text, or the same name with mostly the same text, for example one imported from `~/.agents/skills` and one from `~/.claude/skills`), the item page says so and offers **Consolidate…**: compare the copies side by side, keep one, optionally take the text from another, and merge tags. The other copies go to Trash marked "Merged into …", their installed folders count as the kept item's and can be updated to it, and **Not duplicates** stops the notice on every machine. Both can be undone.

**Installing and keeping copies honest**

- **Machines** is available in every build. It shows this machine as one grid of skills and agents against locations (personal and project folders): installed, changed outside Kiln, an update available, or off. Click a cell to install, update, remove, compare or **Keep these changes**. Adding other machines is coming soon.
- **Install into project…** puts a skill into any project folder with a preview of the destination; project copies appear under Projects.
- **Updates** never overwrite a copy that was edited outside Kiln, a different copy, or a link; the message names each copy it skipped.
- **Keep these changes** saves a copy edited in its folder as a new draft, and approving it adopts the folder as it is.

**Around the app**

- **Capture** opens as a dialog from the Capture button, Ctrl+N, a paste or a drop, and detects what you gave it: a YouTube link offers **Distill video**, a link **Analyze page**, text **Save as draft**.
- **Status bar.** The GitHub state (Up to date, N new · Pull, N waiting to push, Offline) and agent runs (running, queued, finished in the last 30 minutes, with Open and Cancel). A toast says when a run finishes; a desktop notification does when Kiln is in the background.
- **Config files** are grouped by agent and project, with missing files folded away. Claude settings get **Permissions** (Allow / Ask / Deny rule chips), **Hooks** and **Raw**, kept in sync.
- **Background sync** checks GitHub every few minutes. All background Git work (approvals, organisation changes, fetches, pulls) now runs through one queue, so none of it can collide.

Also in this release:

- The stored status "captured" reads **Draft** everywhere.
- Your library, its format and your approvals are unchanged; 0.22.0's saved experimental switches are ignored and dropped the next time settings are saved.

If you're on 0.20.0 or later with Windows, the AppImage or the .deb, Kiln offers this update itself. On macOS and the tar.gz it links to this page. The `latest*.yml` files are the update feeds the app reads; you don't need to download them.

Validation: before tagging, the type check and 305 unit tests (304 passed, one skipped) passed on Windows, macOS and Linux in CI, and so did the Electron desktop suite (54 passed, 4 skipped). The desktop specs were rewritten for the new UI; every screen was also checked in both themes against the real backend with the seeded demo library. A dry run of the release workflow built all three platforms and started each packaged app once. The redesign was tried by hand from a source build on Linux; the packaged builds have not been clicked through by hand.
