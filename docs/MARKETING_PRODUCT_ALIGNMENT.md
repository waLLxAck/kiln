# Marketing and desktop product alignment

Research date: 25 September 2026. Baseline: `2fe1c68`, before the accompanying onboarding and library fixes. Scope: first-party source inspection of this checkout. This is a research note, not approval for a redesign. The deployed website and released Windows executable were not visually compared, and no user study was conducted. Findings about confusion are hypotheses supported by the implementation differences below.

## Finding

The mismatch is more than branding. The homepage presents an interactive, application-shaped interface whose navigation and task arrangement differ from the desktop. Someone can learn where to click in the advertisement and then be unable to find the equivalent control in the product. Marketing explicitly documents its interface as sample state, but that does not establish that visitors understand the layout itself is illustrative. [Marketing implementation notes](../apps/marketing/README.md), [sample window and panel](../apps/marketing/src/panel.ts), [desktop shell](../apps/desktop/src/App.tsx).

## Options

These are proposals derived from the differences above, not measured usability results.

1. **Make the website demonstrate the shipping product.** Keep the founder's annotated-paper presentation around a real application screenshot or recording. Show Library → Skills → selected item → installations, and the real capture/test path. Label the existing interactive model “Illustrated workflow; the app layout differs” if it remains. This addresses the immediate expectation gap without changing the desktop information architecture. Its tradeoff is losing some of the simplified demo's immediacy.
2. **Bridge the advertised task into onboarding.** Introduce provider/location selection, discovery of skills and agent definitions, an import summary, and a direct route to the resulting library. State the GitHub prerequisite alongside download/setup expectations. Offer “Let Kiln manage existing copies” as a previewed follow-up with clear treatment of matching, edited and linked copies. This improves first use, but by itself does not create the advertised matrix. The existing scan, adoption and replacement states provide implementation building blocks. [Current install and scan states](../apps/desktop/src/Skills.tsx).
3. **Investigate a real inventory view.** Prototype a skill-by-location matrix as a dedicated view or an alternate Skills layout, retaining the existing detail pane for content/history. Include found copies, drift, links, exact paths and unavailable locations. Test it on a large library and many project folders before committing to it. The benefit is matching the principal marketing interaction; the cost is a new maintained view and difficult width/scaling decisions.
4. **Align selected visual tokens after task alignment.** A warmer surface palette or selected typography could improve recognition, but it cannot make the missing matrix or adjacent panes appear. Preserve state contrast and desktop dark mode. Alternatively, render the website's embedded product frame using the desktop's existing visual style, while leaving the red-pen editorial wrapper intact.

Recommended sequence: accurate product imagery and scope wording first; onboarding/discovery improvements alongside the reported fixes; validate an inventory-view prototype before choosing a desktop redesign. Bulk management should be described separately from deletion: library removal, local-copy removal and broken-entry cleanup have different consequences. Existing library multi-selection, removal preview and per-location cleanup mean this should be assessed as discoverability and coverage, rather than assuming all bulk functionality is missing. [Library selection/actions](../apps/desktop/src/App.tsx), [bulk removal preview](../apps/desktop/src/BulkLibrary.tsx), [cleanup](../apps/desktop/src/Skills.tsx).

## How to validate the next decision

Use the same synthetic library in the released desktop and proposed marketing imagery. Include shared and client-specific folders, an edited copy, a link, an imported draft and an agent definition. Keep sample labels visible; do not use someone's private library in public screenshots.

Ask new users who have seen the page to locate an installed skill, explain which folders contain it, import existing skills, remove an unwanted local copy and test a captured prompt. Observe wrong turns, completion, and whether they understand import versus approval versus installation. Specifically ask which first screen they expected after download. These tasks follow the advertised flows and the existing product states above; success thresholds should be agreed before conducting the study.

Record results against the exact app version and website revision. This research identifies source-level divergence; it does not establish its prevalence or justify reproducing the illustrative interface wholesale.
